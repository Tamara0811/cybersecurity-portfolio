# Network Traffic Analysis with Wireshark

## Overview

This project demonstrates a basic network traffic investigation using Wireshark. The goal was to capture and analyze network packets, identify DNS activity, examine communication between source and destination IP addresses, and observe encrypted web traffic using QUIC/HTTPS.

This lab was completed as part of my hands-on cybersecurity training and focuses on skills relevant to an entry-level SOC Analyst role.

## Tools Used

- Wireshark
- Windows
- Google Chrome
- DNS
- TCP/IP
- UDP
- QUIC / HTTPS

## Investigation Objectives

The main objectives of this investigation were to:

- Capture live network traffic
- Apply Wireshark display filters
- Identify DNS queries and responses
- Determine source and destination IP addresses
- Analyze UDP communication
- Identify encrypted QUIC/HTTPS traffic
- Inspect individual packets and protocol details
- Understand how DNS resolution leads to communication with remote servers
- Distinguish normal network activity from traffic that may require further investigation

## Traffic Capture

Wireshark was used to capture network traffic generated while browsing the web.

The capture contained multiple network protocols and connections between the local system and external servers.

Instead of reviewing every captured packet manually, display filters were used to isolate relevant traffic.

## DNS Analysis

The following Wireshark filter was used:

`dns`

DNS traffic was examined to identify domain name resolution activity.

During the analysis, I reviewed:

- DNS queries generated by the client
- DNS responses returned to the client
- Requested domain names
- Resolved IP addresses
- Source and destination addresses
- UDP-based DNS communication

This demonstrated how a hostname is translated into an IP address before communication with the destination server occurs.

## IP Address Analysis

Packet details were inspected to identify the systems participating in the communication.

Important fields included:

- Source IP address
- Destination IP address
- Source port
- Destination port
- Transport protocol
- Packet length
- Packet timestamps

These fields can help a SOC analyst understand which systems are communicating and determine whether additional investigation is necessary.

## QUIC and HTTPS Traffic

Encrypted web traffic was also observed during the investigation.

QUIC traffic was identified in Wireshark. QUIC commonly operates over UDP and is frequently associated with encrypted HTTPS communication.

Although the application data itself was encrypted, useful metadata remained visible, including:

- Source and destination IP addresses
- UDP ports
- Packet sizes
- Communication direction
- Connection patterns

This demonstrates an important concept in network security: encrypted traffic can still provide useful information during an investigation even when the payload cannot be directly inspected.

## Packet Investigation

Individual packets were inspected using Wireshark's packet details pane.

The investigation involved reviewing different protocol layers and understanding how information is encapsulated as it travels across the network.

Examples of information examined included:

- Ethernet frame information
- IP addressing
- UDP communication
- DNS information
- QUIC traffic
- Source and destination ports

## Security Relevance

Network traffic analysis is an important part of security monitoring and incident investigation.

A SOC analyst may use packet analysis to investigate:

- Suspicious outbound connections
- Communication with malicious domains
- Unexpected DNS requests
- Malware command-and-control traffic
- Unusual network behavior
- Potential data exfiltration
- Connections to suspicious external IP addresses

A packet capture does not automatically indicate malicious activity. Findings must be evaluated together with additional context and security telemetry.

## Investigation Workflow

A simplified investigation workflow used in this lab was:

1. Capture network traffic.
2. Identify relevant protocols.
3. Apply Wireshark display filters.
4. Review DNS queries and responses.
5. Identify resolved IP addresses.
6. Examine source and destination communication.
7. Inspect QUIC/HTTPS traffic.
8. Review packet-level details.
9. Determine whether the observed activity appears expected or requires additional investigation.

## Example Wireshark Filters

Filters used or relevant to this investigation include:

`dns`

`udp`

`tcp`

`quic`

`tcp.port == 443`

`udp.port == 443`

`ip.addr == <IP_ADDRESS>`

These filters allow an analyst to reduce a large packet capture to traffic relevant to a specific investigation.

## Key Findings

The investigation demonstrated the relationship between DNS resolution and subsequent network communication.

DNS queries revealed which domains the system attempted to resolve, while later packets showed communication with the corresponding external infrastructure.

Encrypted protocols such as QUIC protected the application payload but still exposed network metadata that could be useful during security analysis.

No conclusion about malicious activity should be made from a single packet or connection alone. Additional evidence such as endpoint logs, DNS reputation, authentication logs, firewall logs, and SIEM alerts may be required.

## SOC Analyst Perspective

If similar traffic appeared during a real SOC investigation, I would correlate the packet capture with additional information such as:

- SIEM alerts
- Firewall logs
- Endpoint telemetry
- DNS logs
- Threat intelligence
- Authentication activity
- User activity

If a suspicious domain or IP address were identified, I would investigate its reputation, determine which endpoint initiated the connection, identify the associated process where possible, and escalate or contain the activity according to the incident response procedure.
